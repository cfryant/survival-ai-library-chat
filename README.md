# Survival AI – Library Chat

Offline survival Q&A that answers **from your own PDF library, with page citations**.
Portable llama.cpp + standard-library Python, for Windows. No internet needed, nothing installed on `C:`.

- You ask a question in the browser; **Library Chat** searches a pre-built text index of your PDF guides (BM25),
  sends the best passages to a local `llama-server`, and streams back an answer that cites them as `[1]`, `[2]` …
- Every source is listed with its file path and page, and is a link that opens the PDF **at the cited page** in a bundled,
  offline copy of Mozilla's **PDF.js viewer**. This works in any browser, including Brave and phones/tablets that ignore `#page=`
  or have no built-in PDF viewer (links stay clickable while the answer is still streaming).
- Each source also has a **Download PDF** button to save the whole guide, and the viewer has its own always-visible
  **Download this PDF** button (also on narrow / mobile screens). A small "raw PDF" link opens the file directly as a fallback.
- The chat page is mobile-friendly (tested at 375 px wide).
- Everything binds to **127.0.0.1 only**. Nothing is sent anywhere; it runs from a USB / portable drive.

> **Safety:** the AI can be wrong. Its answers are **not medical certainty**. The official guides always win –
> check the page it cites. In a real emergency call 911 (or your local emergency number) if you can.

## Folder layout

This repository is the contents of the `AI` folder of the kit (plus `KIT-README.txt`, which goes in the kit root).

```
<Kit>\
├─ KIT-README.txt                  <- end-user "start here" sheet (copy from this repo)
├─ Survival Library\               <- your PDFs, in topic folders
│  ├─ 01 First Aid & Medical\*.pdf
│  ├─ 02 Water\*.pdf  ...
│  ├─ MANIFEST.csv                 <- optional: columns "file" (path relative to Survival Library) and "title"
│  └─ INDEX.html                   <- optional: your own start page for browsing the PDFs
└─ AI\                             <- this repo
   ├─ Start Survival AI (battery).bat
   ├─ Start Survival AI (plugged in).bat
   ├─ Start Survival AI (lowest power, built-in GPU).bat
   ├─ Stop Survival AI.bat
   ├─ _launch.cmd                  <- shared launcher used by the Start*.bat files
   ├─ app\                         <- NOT in the repo (download, see below)
   │  ├─ cuda\llama-server.exe     <- llama.cpp CUDA 12.4 build + cudart DLLs
   │  ├─ vulkan\llama-server.exe   <- llama.cpp Vulkan build
   │  ├─ cpu\llama-server.exe      <- llama.cpp CPU build
   │  ├─ python\python.exe, pythonw.exe   <- Python embeddable package
   │  └─ pylib\pypdf\              <- pypdf (only needed to build the index)
   ├─ models\                      <- NOT in the repo: GGUF model files
   ├─ config\
   │  ├─ system-prompt.txt         <- generated by make_prompt.py
   │  ├─ webui-battery.json        <- generated by make_prompt.py (plain web UI, 512 max tokens)
   │  └─ webui-plugged-in.json     <- generated by make_prompt.py (plain web UI, 1024 max tokens)
   ├─ library-search\
   │  ├─ server.py                 <- Library Chat server (stdlib only), 127.0.0.1:8081
   │  ├─ index.html                <- Library Chat page
   │  ├─ viewer-addon.css / .js    <- Library Chat's download button + mobile tweaks for the PDF.js viewer
   │  ├─ pdfjs\                    <- Mozilla PDF.js v6.4.299 prebuilt viewer (bundled, Apache-2.0, see pdfjs\LICENSE)
   │  ├─ build_index.py            <- extracts PDF text -> index\chunks.json (needs pypdf)
   │  ├─ make_prompt.py            <- writes config\ from Survival Library\MANIFEST.csv
   │  ├─ Rebuild library index.bat <- runs build_index.py + make_prompt.py
   │  └─ index\chunks.json         <- generated, not in the repo
   └─ logs\                        <- created at runtime
```

Paths are all relative to the scripts (`%~dp0` in the batch files, `__file__` in Python), so the kit works from any drive letter.

> `config\system-prompt.txt` and the two `webui-*.json` files in this repo contain an **example** list of guide file paths
> from the original library. They are regenerated from your own `Survival Library\MANIFEST.csv` when you run
> `make_prompt.py` (or `Rebuild library index.bat`), so replace them for your library.

## Prerequisites (official download sources)

| Piece | Where to get it | Put it in |
|---|---|---|
| **llama.cpp** Windows release builds – tested with **b11669** | <https://github.com/ggml-org/llama.cpp/releases> (e.g. [b11669](https://github.com/ggml-org/llama.cpp/releases/tag/b11669)) | see below |
| &nbsp;&nbsp;CUDA (NVIDIA): `llama-bXXXX-bin-win-cuda-12.4-x64.zip` **plus** `cudart-llama-bin-win-cuda-12.4-x64.zip` | same release page | `AI\app\cuda\` (unzip both into the same folder) |
| &nbsp;&nbsp;Vulkan (any GPU, incl. integrated): `llama-bXXXX-bin-win-vulkan-x64.zip` | same release page | `AI\app\vulkan\` |
| &nbsp;&nbsp;CPU only: `llama-bXXXX-bin-win-cpu-x64.zip` | same release page | `AI\app\cpu\` |
| **Python embeddable package** (Windows x86-64, 3.10 or newer) | <https://www.python.org/downloads/windows/> → "Windows embeddable package (64-bit)" | `AI\app\python\` (must contain `python.exe` and `pythonw.exe`) |
| **pypdf** (pure Python; only used by `build_index.py`) | <https://pypi.org/project/pypdf/> | `AI\app\pylib\` (so that `AI\app\pylib\pypdf\` exists) |
| **GGUF models** | Hugging Face. See **[MODELS.md](MODELS.md)** for verified low-power picks for every kind of hardware (NVIDIA, AMD/Intel, CPU-only, Mac, iPhone/iPad, Android, Raspberry Pi) | `AI\models\` |
| &nbsp;&nbsp;`Qwen3.5-4B-Q4_K_M.gguf` (battery / lowest power) | <https://huggingface.co/unsloth/Qwen3.5-4B-GGUF> | `AI\models\` |
| &nbsp;&nbsp;`Qwen_Qwen3.5-9B-Q4_K_M.gguf` (plugged in) | <https://huggingface.co/bartowski/Qwen_Qwen3.5-9B-GGUF> | `AI\models\` |

Notes:
- The launchers reference the model files by exact name. If you use a different file (for example unsloth's
  `Qwen3.5-9B-Q4_K_M.gguf`), edit the first argument in the matching `Start Survival AI (...).bat`.
- To install pypdf without installing anything on the PC, either run `pip install --target AI\app\pylib pypdf`
  on any machine with Python, or download the `pypdf-*.whl` file from PyPI (a wheel is a zip) and extract its `pypdf\` folder into `AI\app\pylib\`.
- `curl.exe` (built into Windows 10/11) is used for health checks.
- Library Chat (`server.py`) needs only the Python standard library.
- The PDF viewer is **already included** in `library-search\pdfjs\`: Mozilla PDF.js **v6.4.299**, generic (modern-browser) build,
  unmodified, from <https://github.com/mozilla/pdf.js/releases/download/v6.4.299/pdfjs-6.4.299-dist.zip>
  (SHA-256 `f2245eb7ef3f674c872fe568a177bfec15874f5c034613e55d8e307f93ebd86d`), with the `*.map` source maps and the sample PDF removed.
  To update it, unzip a newer `pdfjs-X-dist.zip` from <https://github.com/mozilla/pdf.js/releases> over that folder. For very old
  browsers you can use the `pdfjs-X-legacy-dist.zip` from the same release instead. It makes no internet requests.

## Install, step by step

1. Create `<Kit>\AI\` on your portable drive and copy the contents of this repo into it
   (download the release zip, or `git clone`). Copy `KIT-README.txt` to `<Kit>\` if you want the end-user start sheet.
2. Download the llama.cpp builds, Python embeddable, pypdf and the models listed above into `AI\app\…` and `AI\models\`.
3. Put your PDFs into `<Kit>\Survival Library\` (topic sub-folders are fine). Optionally add a `MANIFEST.csv`
   with `file,title` columns to give nicer titles; `make_prompt.py` needs it to write the plain-chat file list.
4. Build the search index: double-click `AI\library-search\Rebuild library index.bat`
   (or run `AI\app\python\python.exe AI\library-search\build_index.py`). This writes `library-search\index\chunks.json`.
   **Re-run it every time you add or change PDFs.** Scanned PDFs with no text layer are reported as warnings.
5. Generate the prompts: `Rebuild library index.bat` also runs `make_prompt.py`
   (or run `AI\app\python\python.exe AI\library-search\make_prompt.py`), which rewrites `config\system-prompt.txt`
   and the two `webui-*.json` files from `MANIFEST.csv`.
6. Double-click a **Start Survival AI** launcher. When done, run **Stop Survival AI.bat**.

## What each launcher does

| Launcher | Model | Context | Max reply | Passages / question | Backend order |
|---|---|---|---|---|---|
| `Start Survival AI (battery).bat` | Qwen3.5-4B Q4_K_M | 4096 | 512 tokens | 4 | CUDA → Vulkan → CPU |
| `Start Survival AI (plugged in).bat` | Qwen3.5-9B Q4_K_M | 8192 | 1024 tokens | 6 | CUDA → Vulkan → CPU |
| `Start Survival AI (lowest power, built-in GPU).bat` | Qwen3.5-4B Q4_K_M | 4096 | 512 tokens | 4 | Vulkan on the integrated GPU → CPU |

All of them call `_launch.cmd`, which:
- tries each backend in order (CUDA only if `nvcuda.dll` exists, Vulkan only if `vulkan-1.dll` exists, CPU always) and
  falls through to the next one if the server does not become healthy;
- in lowest-power mode lists Vulkan devices and picks the integrated GPU (Intel / Radeon / Iris / UHD / Arc) so a discrete GPU can stay asleep, or falls back to CPU;
- starts `llama-server` on **127.0.0.1:8080** (threads = physical cores, max 8; `--offline`; reasoning off;
  **the model unloads after 5 idle minutes** via `--sleep-idle-seconds 300`); the plain llama.cpp web UI there uses the matching `config\webui-*.json`;
- starts **Library Chat** (`server.py` with the portable `pythonw.exe`) on **127.0.0.1:8081** and opens it in the browser.
  If the index has not been built, it opens the plain chat on 8080 instead;
- writes logs to `AI\logs\`. If an AI is already running it just reopens the chat (run Stop first to switch models).

**`Stop Survival AI.bat`** kills `llama-server.exe` and the Library Chat process (by the PID in `logs\library-chat.pid`) to free GPU and memory.
Note: it stops *every* `llama-server.exe` on the PC.

## Library Chat details

- `GET /` chat page, `GET /api/info` index stats, `GET /api/search?q=` raw passage search, `POST /api/chat` (OpenAI-style messages, SSE stream with a leading `{"sources": [...]}` event), `GET /pdf/<path>` serves PDFs from `Survival Library` only (path-traversal checked; HTTP Range supported; add `?dl=1` to download
  as an attachment), `GET /pdfjs/...` serves the bundled PDF.js viewer, e.g. `/pdfjs/web/viewer.html?file=%2Fpdf%2F<url-encoded path>#page=12`.
- Options: `--port 8081 --llama http://127.0.0.1:8080 --k 4 --max-tokens 512 --mode <label> --pidfile <file>`.

## Safety

This is a reading aid for official guides, not a doctor. The AI can misread or invent details. **The official guides win
over AI answers**, always check the cited page, and nothing here is medical certainty. Read the PDFs directly when you can
(it also uses the least battery).
